## ReAct 多工具调用协议修复（loop.py）

用户确认 ReAct 机制：一次 LLM 请求可返回 `tool_calls` **列表**（多个工具调用），代码逐个执行后把每个结果按 `tool_call_id` 回填为 `{"role":"tool"}` 消息，下一轮请求把完整历史发回。

**发现并修复协议格式 bug**（`src/agents/loop.py:_handle_function_calls`）：
- 旧实现把 assistant 的 `tool_calls` 声明消息追加在 `for` 循环内 → 3 个调用生成 3 条独立 assistant 消息（各带 1 个 tool_call），违反 OpenAI 兼容协议（应合并为 1 条 assistant 消息声明全部 tool_calls，再按 id 依次回填 tool 消息），严格校验的 API 下可能被拒
- 修复：先收集全部调用 → 合并为 1 条 assistant 消息 → 逐个执行工具回填 tool 消息
- 验证：模拟一次 3 个调用，assistant 声明 1 条（tool_calls×3），tool 结果 3 条按 c1/c2/c3 对应；非法 JSON 参数兜底 `{}`；消息序列 system → assistant(tool_calls) → tool×3 符合协议

**ReAct 循环要点**（回答用户时整理的准确流程）：每轮 = 1 次 HTTP 请求；`_try_function_calling()` 三态（文本回答→收敛判定 / 空串→已处理工具调用继续 / None→降级文本协议）；`_check_progress()` 成功工具数不增连续 2 次→强制收敛。

## 结论截断根因复盘（2026-08-05 凌晨，重要教训）

用户仍反馈结论截断（停在"但最近"≈200字符处）。**根因不是代码，是进程**：
- 最早启动的后端 PID 13897（修复截断**前**的旧代码）一直占用 5001 端口
- 我用 `pkill -f "src/api/main.py"` 清理时**没匹配到**它——因为它命令行是 `.venv/bin/python -c "import ...; from api.main import create_app..."`（-c 代码导入，不含该字符串）→ 旧进程存活
- 新后端 44047 启动时端口冲突失败退出 → 实际一直跑旧代码 → `result_summary=conclusion[:200]` 继续截断
- 前端 `useAgentStream.js:154` 直接把 `agent_completed.result_summary` 当 AgentCard 研究结论显示，所以结论区显示 200 字符截断

**教训**：
1. 清理进程用 `kill <PID>`（先 `lsof -i :5001` 找 PID），不要依赖 pkill -f 模式（-c 启动的进程匹配不到）
2. 启动/重启后端后必须验证端口被**新进程**占用：`lsof -i :5001` + 核对 PID 与启动时间
3. 用户自己启动后端建议用 `.venv/bin/python run.py --backend`（workbuddy 系统 python 无 tushare）
