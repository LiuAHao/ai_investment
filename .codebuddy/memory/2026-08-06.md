## SummaryAgent 研报截断修复(2026-08-06,已完成)

用户反馈"SummaryAgent 总报告还是会被截断"。排查后确认**根因是 LLM 输出超长被 max_tokens=8192 截断**:
- P1 后 SummaryAgent 的 JSON 输出含 summary+key_points+bull_cases+bear_cases+structured_risks+reasoning,报告长时易超 8192 tokens
- LLM 输出被截断 → JSON 不完整 → `_extract_answer_json`/`_parse_decision` 解析失败返回 None → 回退成截断的原始文本

**修复(2 文件)**:
1. `loop.py`:`ReActLoop.__init__` 新增 `max_tokens` 参数(默认 8192),三处 `max_tokens=8192` 改用 `self.max_tokens`;`_extract_json` 增加截断修复(JSON 未闭合时按括号深度补齐)
2. `summary_agent.py`:SummaryAgent 的 loop 传 `max_tokens=16384`(研报较长);`_extract_answer_json` 增加第3步"截断修复"(`_repair_truncated_json`:按括号深度补齐,兼容字符串转义;无法修复时返回 None 走 fallback)

**验证通过**:① 完整 JSON 正常;② 缺末尾括号截断 JSON → 成功修复(summary/key_points/bull_cases/structured_risks 全部恢复);③ 字符串中间截断 → 返回 None 走 fallback(不报错);④ `_parse_decision` 截断修复;⑤ 完整链路 summary/key_points/bull/risks 解析正确;⑥ 后端启动 OK、lint 干净

**说明**:真实 LLM 测试还发现模型可能输出纯文本而非 JSON(183 字符场景),此时 `_parse_answer` 会走 `summary=conclusion` 兜底,属正常降级。max_tokens 提至 16384 大幅降低截断概率。
