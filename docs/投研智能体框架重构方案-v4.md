# 投研智能体框架重构方案 v4

> 状态：已实施（阶段 0-6，2026-10-22）
> 日期：2026-10-22
> 范围：`src/agents/` 全量重构、`src/tools/` 补齐、`src/rag/` 删除、SSE 事件契约升级
> 目标：把"三路并行调研 + 单次总结"的线性工作流，升级为"取证 → 论点 → 对抗 → 裁决 → 质检 → 结算"的闭环投研系统

---

## 0. 结论先行

三条判断，先说清楚，后面全部围绕它们展开。

1. **现状不是"多 Agent"，是"一次并行检索 + 一次总结"**。三个调研 Agent 互不可见（共享池实际在 function calling 路径下几乎不广播，见 §2.2），编排层没有重规划，总结层只拿到各路 `conclusion` 文本、拿不到任何原始数字（`summary_agent.py:166` 只拼 `conclusion` + 最近 3 条思考）。所以"严谨"不是靠加 prompt 能补的，是信息在编排边界被丢掉了。

2. **多空辩论值得做，但不能照抄自由辩论**。业界已验证的结构是 TradingAgents（分析师 → 多空研究员辩论 → 交易员 → 风控 → 组合经理）和 FinCon（经理-分析师层级 + 风险控制 + 跨回合信念更新）。但 2025 年的多智能体辩论研究一致指出两个失败模式：**谄媚（sycophancy）导致过早共识**、**锚定导致裁判被首轮立场带走**。照抄"正反方聊两轮 → 裁判总结"会稳定产出"看起来平衡、实际没有信息增量"的报告。本方案的对抗层用**结构化辩论协议 + 先盲判后裁决 + 可证伪条件**来对冲这两点（§5.3、§5.4）。

3. **RAG 可以删，但"沉淀"不能一起删**。现在 RAG 承担两件事：静态教材检索（价值接近零，且内容网络可替代）和 L3 结论沉淀（有价值，但用向量库存自然语言结论是最差的一种记忆）。删掉向量检索后，用**结构化 DecisionRecord + SQLite 查询 + 结算反思**替代它——这才是能形成闭环、能被审计、能被校准的东西（§6.5）。

4. **定位与回测已定案**（grilling 结论，详见 `docs/投研智能体框架-决策记录与回测设计.md`）：系统交付「方向判断 + 置信度 + 仓位区间 + 触发条件」，不做确定性买卖指令；回测定位为**系统校准器**而非收益证明，主指标是置信度校准（Brier）、辩论增量（有/无对比）、分析师贡献（ablation），收益只作辅助列；数据以 tushare 为主，启动时做 capability probe，不可用接口降级 akshare 并标注来源。

另外一句实话：**现在的工具集撑不起"基本面分析师"**。全项目没有三大报表、没有财务指标时序、没有公告、新闻只有 ddgs 且带进程级串行锁（`utils/web_search.py:17`）。不做 §8 的数据补齐，新框架里一半的角色是空壳。

## 1. 行业调研：四条主流路线与可借鉴点

### 1.1 TradingAgents（Tauric Research, arXiv 2412.20138）

角色分工：基本面/情绪/新闻/技术分析师 → 多空研究员辩论 → 交易员 → 风控团队 → 组合经理。

工程上真正有价值的部分（v0.5+ README），比论文架构更值得抄：

| 机制 | 做法 | 对我们的意义 |
|---|---|---|
| 结构化状态 + 自由辩论混合 | 分析师报告写入全局 state，Agent 直接查事实，不靠长对话传递 | 直接对应我们要建的 EvidenceLedger |
| 快慢模型分层 | quick model 跑分析师/辩论，deep model 跑研究经理/组合经理 | 可以立刻落地，成本可控 |
| verified data snapshot | 行情断言必须落到已验证快照，防价格幻觉 | 分析师只能引用 Ledger 里的 evidence_id |
| 决策记忆 + 结算 | 每次决策写入 memory log，持有期到点结算真实收益/alpha，生成一段反思，组合经理下次读取 | 这就是"闭环"的标准答案，替代 RAG 沉淀 |
| point-in-time 数据 | 回测时只用当日已发布的数据 | 如果要做回测，必须这样；否则收益全是未来函数 |
| 结构化输出管理器 | Research Manager / Trader / Portfolio Manager 用结构化输出 | Judge 和 Verdict 必须结构化 |

### 1.2 FinCon（NeurIPS 2024, arXiv 2407.06567）

- **经理-分析师层级**，不是全员互聊。分析师各管一路数据源，经理汇总决策。降低通信成本，避免 StockAgent 那种"多 Agent 长讨论、慢且目标模糊"。
- **双级风险控制**：回合内用 CVaR 监控下跌风险；回合间用 Conceptual Verbal Reinforcement，比较两轮盈利差异，把"哪种信息源更有用"抽象成信念，选择性回灌给相关分析师。
- 消融很硬：去掉 CVaR，组合收益从 113.8% 掉到 14.7%；去掉信念更新，掉到 28.4%。说明**风险约束和经验回灌是收益主因，不是 Agent 数量**。
- 可借鉴的降级版：我们不做强化学习，只做"结算后生成一条结构化反思，下次同类任务注入对应分析师的 prompt"。这是 CVRF 的最小可用形态。

### 1.3 ai-hedge-fund（virattt）

- 19 个 Agent：6 个分析型（估值/情绪/基本面/技术/成长/新闻）+ 13 个投资哲学人格（巴菲特、格雷厄姆、Burry、Taleb…）+ 风控 + 组合经理。
- 用 LangGraph 编排，共享 `AgentState`，每个 Agent 输出 `bullish/bearish/neutral` 信号，组合经理聚合仓位。
- **可借鉴**：信号统一成枚举 + 置信度，聚合层做加权而不是让 LLM 自由发挥。
- **不该抄**：人格化 Agent（"巴菲特会怎么看"）适合教学演示，不适合追求可复现的投研。人格 prompt 会引入大量无法证伪的叙事。我们要的是**方法论分工**，不是人格扮演。

### 1.4 Apex Quant / 多智能体辩论研究

- Apex Quant：激进多头（Zealot）+ 激进空头（Reaper）+ 中立 CIO（Fulcrum），三轮结构化辩论后出决策。
- 辩论有效性研究（NeurIPS 2025, arXiv 2510.12697）：辩论确实优于多数投票，但**必须有自适应停止机制**，否则成本爆炸且后期轮次没有信息增量。
- 谄媚研究（arXiv 2509.23055）：多智能体辩论的核心失败模式是 sycophancy，会导致"分歧坍缩"，准确率甚至低于单 Agent。失败分两类：辩手驱动（一方直接投降）和裁判驱动（裁判迎合多数）。
- **结论**：辩论必须设计成"有成本的对抗"，而不是"请两位专家聊聊"。

### 1.5 横向对比与我们的定位

| 维度 | TradingAgents | FinCon | ai-hedge-fund | 本方案 |
|---|---|---|---|---|
| 核心目标 | 交易决策 | 交易/组合 | 信号演示 | **研究结论 + 可审计决策** |
| 分析师分工 | 4 类 | 7 类（含音频） | 6 类 + 人格 | 4 类，按证据类型分 |
| 对抗机制 | 自由辩论 1-2 轮 | 无辩论，经理裁决 | 无辩论，信号聚合 | **结构化辩论 2 轮 + 攻击类型约束** |
| 防谄媚 | 弱 | 不适用 | 不适用 | **独立建论 + 先盲判 + 必须让步或说明** |
| 风险控制 | 风控团队 | CVaR + 信念 | 风控 Agent | 结构化风险矩阵 + 仓位区间建议 |
| 记忆/闭环 | decision log + 结算 | 跨回合 CVRF | 无 | **DecisionRecord + 前向结算 + 反思回灌** |
| 数据要求 | 高（SEC/行情/社媒） | 高（10-K/ECC） | 中 | 中（先补 A 股财务/公告） |

## 2. 现状诊断（基于代码实测，不是推测）

### 2.1 结构性问题

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| S1 | 拓扑静态，不可重规划 | `orchestrator.py:256` `_decide_plan` 一次性决定，此后无 replan 点 | 中途发现数据缺口无法补派 |
| S2 | 并行数写死 3，且无超时 | `orchestrator.py:376-383`，`future.result()` 无 timeout | 一个 LLM 慢调用挂住整任务 |
| S3 | 原始数据在编排边界全部丢失 | `summary_agent.py:166-177` 只取 `conclusion` + `thinking_log[-3:]` | 总结层无法核验任何数字，"双源核验"是空话 |
| S4 | `risk_preference` 是死参数 | 传入 `run_query` → 存进 `AgentTask` → `base._build_user_message` 不读 | 用户风险偏好从未进入任何 prompt |
| S5 | 证据无法追溯 | `loop.py:608-616` 生成 `tool:step_id`，`step_id` 从无赋值 | `evidence_refs` 无法点回原始数据 |
| S6 | 失败静默传播 | `base.py:102-112` 任何异常 → `degraded=True` 空结论；`_compute_confidence` 只扣 0.1 | 缺一路也能产出一份"完整研报" |
| S7 | `EvidenceItem` / `IntentResult` / `ResearchContext` 定义未使用 | `state.py:125/76/193` | 设计意图存在，实现缺失 |

### 2.2 共享发现池实际近乎失效（关键）

- 广播只发生在 `loop.py:120-121`：`_try_function_calling` 返回**非空文本**时才调 `_publish_findings`。
- function calling 正常工作时，模型通常只返回 `tool_calls`、不写正文 → `text_answer == ""` → 直接 `continue`，**不广播**。
- 也就是说：共享池生效的前提，是模型"一边调工具一边额外写一段 `[FINDINGS]`"，这与 FC 的典型行为相反。
- 第二轮触发条件是 `len(findings) >= 2 or 种类 >= 2`（`orchestrator.py:429-437`），池子空就跳过。实际就是"经常不触发"。
- 即使触发，共享内容是自由文本 + `SequenceMatcher >= 0.88` 去重（对中文长句误判率高），无来源、无时间、无口径、无 evidence_id，无法被下游引用。

**结论：不要再修这个机制。直接换成结构化 Ledger。**

### 2.3 数据与工具短板

| 能力 | 现状 | 影响 |
|---|---|---|
| 行情 | A 股/指数/ETF/基金/港股/全球指数日线，A 股实时快照 | 够用 |
| 估值 | PE/PE_TTM/PB/PS/股息率/换手/市值，仅最新一条 | 够用，但无历史分位 |
| 技术指标 | 仅 MA + 趋势 + 动量，无 MACD/RSI/KDJ/布林 | 技术分析师能力偏弱 |
| 财务 | **完全缺失**（无三大报表、无 ROE/毛利率时序） | 基本面分析师无米下锅 |
| 公告 | **完全缺失** | 事件驱动研究缺失 |
| 新闻 | 仅 ddgs 网页搜索，无发布时间、无来源可信度 | 舆情分析质量低 |
| 新闻并发 | `_SEARCH_LOCK` 进程级串行锁，排队超时返回空 | **多 Agent 并行时互相饿死**（这正是历史记录里 NewsAgent 反复重试耗尽的根因） |
| LLM 超时 | `build_client()` 未设 timeout/retries，走 SDK 默认 600s | 单点挂起风险 |

### 3.2 设计原则

1. **事实与判断分离**：分析师只交证据，不交结论。结论只允许出现在 Thesis / Verdict。这一条直接解决"先定结论后补理由"。
2. **一切引用必须可点回**：任何 claim 里的数字，必须带 `evidence_id`，Verifier 机械校验。
3. **对抗必须有成本**：辩论不允许自由发挥，攻击类型受限、必须引用对方 claim_id、必须点名让步。
4. **裁判先独立、后参考**：盲判记录留档，用于事后校准（判断裁判是否被辩论带偏）。
5. **闭环靠结算，不靠向量**：决策落盘 → 到点结算 → 写反思 → 下次注入。不用 embedding。
6. **预算硬约束**：每阶段有调用/工具预算，超预算降级而不是挂起。

## 4. 分层职责与 Agent 清单

### 4.1 L0 ResearchSupervisor

**不做 ReAct**，单次结构化输出（`response_format=json_object`），因为它是路由，不是研究。

输入：query、session 上下文、用户风险偏好、时间框架、可选持仓。
输出 `ResearchPlan`：

```json
{
  "intent": "single_asset_research | compare | portfolio | macro",
  "assets": [{"asset_id": "stock:600519", "role": "primary"}],
  "horizon": "short | medium | long",
  "required_analysts": ["market", "fundamental"],
  "optional_analysts": ["news"],
  "debate": true,
  "budget": {"llm_calls": 20, "tool_calls": 24},
  "focus_questions": ["Q1 毛利率下滑是结构性的吗", "Q2 政策落地节奏"],
  "excluded_analysts_reason": {"macro": "单票问题，宏观仅作背景"}
}
```

关键变化：

- **规则保底 + LLM 加派**：`required_analysts` 由规则产出（涉及个股必含 market + fundamental；含事件关键词加 news；宏观/指数问题加 macro），LLM 不可删除，只能追加 `optional_analysts`。避免"该查财务却没派"的静默漏检。
- `debate` 由规则计算（争议度触发），LLM 只能建议不能擅自打开。触发条件见决策记录 A/B3。
- `focus_questions` 是本轮研究的验收清单，Verifier 会检查每条是否被回答或明确标注"无法回答"。
- 预算按 `min(用户档位, 硬上限)` 分配，所有阶段读取同一个 budget 对象，不允许各 Agent 自行加码。

### 4.2 L1 分析师层（4 路并行）

| Agent | 职责 | 证据类别 | 工具白名单 |
|---|---|---|---|
| `MarketAnalyst` | 行情、技术形态、估值分位、相对强弱 | price / technical / valuation | `cn_stock_history`, `cn_stock_spot_search`, `us_stock_quote`, `us_stock_history`, `fund_nav_history`, `etf_profile`, `etf_tracking_index` |
| `NewsAnalyst` | 事件、公告、舆情、时间线 | news / announcement | `asset_news_search`, `asset_announcement_search`（新增）, `web_research`（新增，替代裸 ddgs） |
| `FundamentalAnalyst` | 财务质量、成长、同业对比 | fundamental | `stock_financial_summary`（新增）, `stock_financial_indicator`（新增）, `stock_peer_compare`（新增）, `fund_profile` |
| `MacroAnalyst` | 政策、利率、行业景气、指数环境 | macro / policy | `macro_indicator`（新增）, `index_environment`（新增）, `asset_news_search` |

**分析师通过注册表接入，不硬编码**（`src/analysts/registry.py`）：

```python
class AnalystSpec(BaseModel):
    name: str
    role: str
    evidence_categories: list[str]
    tool_names: list[str]
    system_prompt: str
    knowledge_card: str | None = None   # 静态知识卡文件路径，直接拼 prompt，不做检索
    budget: Budget
    required_by: list[str] = []         # 规则保底：满足这些 intent 时必须派发
```

`pipeline.py` 只读注册表；新增分析师 = 注册一个 spec + 写 1 个验收用例，不改编排代码。这是"功能越多越好"不导致范围失控的前提。

**硬性输出契约**（所有分析师相同的 schema）：

```json
{
  "evidence": [
    {
      "category": "fundamental",
      "statement": "2026Q2 单季营收同比 -15.2%",
      "value": -15.2, "unit": "%",
      "caliber": "单季/同比/合并口径",
      "source_tool": "stock_financial_summary",
      "source_time": "2026-08-28",
      "confidence": 0.9
    }
  ],
  "gaps": [
    {"question": "毛利率下滑是否来自产品结构", "reason": "工具未覆盖分产品毛利率"}
  ],
  "coverage": {"asked": 6, "answered": 5, "failed": 1}
}
```

分析师 prompt 里明确禁止出现"因此看多/看空/建议买入"这类结论词。违反的段落由 Verifier 在下游拦截。

**取证循环收敛条件**（替代现在的"无进展计数"）：

- 已覆盖 `focus_questions` 中属于自己的全部问题；或
- 连续 2 次工具调用没有产生新 evidence（按 `(category, statement 归一化)` 判重）；或
- 达到该 Agent 工具预算。

### 4.3 L2 论点层（Bull / Bear）

两者**并行、互不可见**。各自只读 Ledger + 自己的 focus questions，不读对方的输出。

`Thesis` 结构：

```python
class Claim(BaseModel):
    claim_id: str                  # CLM-BULL-01
    statement: str
    evidence_ids: list[str]        # 必须非空
    reasoning: str                 # 从证据到结论的推理链
    strength: Literal["high", "medium", "low"]
    assumptions: list[str]         # 成立所依赖的前提
    falsifiers: list[str]          # 可观测的否证条件，必须具体
    time_horizon: str

class Thesis(BaseModel):
    side: Literal["bull", "bear"]
    core_claim: str
    claims: list[Claim]
    key_assumptions: list[str]
    kill_criteria: list[str]       # 什么情况下这个论点整体失效
    confidence: float
    unanswered_gaps: list[str]
```

规则：

- 每条 `Claim.evidence_ids` 非空，且必须真实存在于 Ledger（Verifier 校验）。
- `falsifiers` 必须可观测。写"如果基本面恶化"不合格，写"若下季度毛利率低于 30% 则本论点失效"合格。
- 单边论据少于 2 条时，该方必须标注 `confidence <= 0.4` 并在 `unanswered_gaps` 说明。这防止和分析师层"证据不足"的情况被忽略。

### 4.4 L3 结构化辩论

不是聊天。每轮是**固定格式的对抗动作**。

**Round 1 — Attack**

每方选择对方**最强的 2 条 claim**（按对方标注的 strength，高优先）发起攻击，每条攻击必须指定类型：

| 攻击类型 | 含义 | 举证要求 |
|---|---|---|
| `evidence_gap` | 该 claim 缺少关键证据 | 指出缺哪个 evidence_id 或哪类数据 |
| `logic` | 从证据到结论的推理不成立 | 复述对方推理并指出断点 |
| `caliber` | 口径混用/不可比 | 指出口径冲突（如 PE 动态 vs TTM、单季 vs 累计） |
| `timing` | 结论与时间框架不匹配 | 指出证据时效或持有期错配 |
| `base_rate` | 忽略基础概率/行业常态 | 给出对照基准 |
| `priced_in` | 已被市场定价 | 引用估值分位或超额收益证据 |

约束：不许引入 Ledger 外的新事实。要引入就必须调工具，且计入预算（默认每方 1 次）。

**Round 2 — Defend / Concede**

每条被攻击的 claim 必须给三选一：

- `defend`：补充推理或引用证据，说明攻击不成立；
- `revise`：下调 strength 或修改表述；
- `concede`：承认失效，明确写出"该 claim 撤回"。

全局硬约束：**若整轮零让步，该方必须在 `no_concession_reason` 中说明至少 150 字，并自动触发 Verifier 对该方的额外核查**。这一条直接对冲谄媚和"死不认错"两种极端。

**停止条件**（满足其一即停，最多 2 轮）：

- 双方论点集合不再变化（claim 文本 + strength 无改动）；
- 新增 evidence 数为 0；
- 分歧点收敛到 <= 3 条且双方对分歧描述一致；
- 达到辩论预算。

### 4.5 L4 Adjudicator

两段调用，刻意分开：

**第一段：盲判（Blind Verdict）**
只给 Ledger + 双方 Thesis（顺序随机、去掉 side 标签），不给辩论记录。输出 `stance / conviction / key_drivers / 主要不确定性`。

目的：留下一个"没有被辩论污染"的基线。事后可以量化"辩论是否改变了判断、改变是否合理"。

**第二段：裁决（Final Verdict）**
给盲判结果 + 完整辩论记录 + 双方 Thesis（恢复标签），要求输出：

```python
class Disagreement(BaseModel):
    topic: str
    bull_view: str
    bear_view: str
    resolvable: Literal["yes", "no", "needs_data"]
    resolution: str | None

class Verdict(BaseModel):
    stance: Literal["bullish", "neutral", "bearish"]
    conviction: float                 # 0-1
    summary: str
    key_drivers: list[str]
    disagreement_map: list[Disagreement]
    falsifiers_to_watch: list[str]    # 未来观察项
    what_would_change_my_mind: list[str]
    position_hint: str                # "0-20% 试探仓位"，禁止"满仓买入"
    blind_stance: str                 # 审计
    revision_reason: str              # 必须写：读了辩论后改了什么，为什么
    confidence_calibration: str       # 本判断最可能错在哪
```

裁判 prompt 的关键约束：

- **不得因为双方"都说得有道理"就给中性**。中性必须给出理由：是证据真的对冲，还是关键数据缺失。两者要在 `key_drivers` 里区分。
- 每个 `key_driver` 必须挂 evidence_id。
- `revision_reason` 若为"无变化"，必须说明辩论未提供新信息；若为"有变化"，必须指出是哪一条攻击/让步导致的。

### 4.6 L5 Verifier（质检）

两级，先机械后 LLM。

**机械校验（纯代码，不调 LLM）**

| 检查 | 失败处理 |
|---|---|
| 所有 `evidence_ids` 存在于 Ledger | 标记 invalid_ref，要求重写受影响 claim |
| 数字与 Ledger 原值一致（容差 0.5%） | 标记 number_mismatch |
| 同一指标口径一致（PE 不混用 TTM/动态） | 标记 caliber_conflict |
| 证据时效 vs 时间框架匹配（短线不用 90 天前新闻做核心论据） | 标记 stale_evidence |
| 引用非空率、claim 覆盖率 | 低于阈值则整体打回 |
| 合规词表（确定性买卖指令、收益承诺） | 命中即阻断 |

**LLM 校验**

- `focus_questions` 是否被回答或明确标注无法回答；
- 是否存在"证据→结论"的逻辑跳跃（只查被引用为 high strength 的 claim）；
- 风险是否被系统性低估（对比 Ledger 中的负面证据数量与 Verdict 中的风险条目数）。

**回退策略**（有界）：

| 问题类型 | 回退目标 | 次数上限 |
|---|---|---|
| 引用不存在 / 数字不符 | 对应 Thesis 或 Verdict 重写 | 1 |
| 证据缺口导致核心问题未答 | 定向补派 1 个分析师（复用其工具白名单） | 1 |
| 风险低估 | Verdict 重写（追加负面证据约束） | 1 |
| 合规命中 | 直接改写为不含指令的表述，不回退 | — |

超过上限则输出 `degraded=true`，并在报告顶部标注"本次结论未通过完整质检"。

### 4.7 L6 Decision & Closure

```python
class DecisionRecord(BaseModel):
    decision_id: str
    session_id: str
    query: str
    assets: list[Asset]
    horizon: str
    as_of: str                        # 决策时点（数据截止）
    verdict: Verdict
    bull_thesis: Thesis
    bear_thesis: Thesis
    evidence_count: int
    evidence_ids: list[str]
    verification: VerificationReport
    price_snapshot: dict              # 决策时价格，用于结算
    settlement: Settlement | None     # 到点后回填
    reflection: str | None            # 结算后生成
    cost: dict                        # llm_calls / tool_calls / tokens
```

存储：`src/data/decisions.sqlite`（单文件，无服务依赖），同时导出 JSONL 便于查看。

结算流程（新增 `src/memory/settlement.py`）：

1. 任务完成后写入 `DecisionRecord`，`settlement=None`。
2. 下次任意任务启动时，扫描 `as_of + horizon` 已到期的记录，拉取区间收益与相对基准（沪深 300 / 标普 500，按资产类型选）。
3. 生成一段 `reflection`：只写"判断对/错 + 归因到哪条 claim + 下次该怎么做"，限 200 字，结构化字段另存（`hit: bool`, `alpha: float`, `miss_reason: Literal[...]`）。
4. 新任务在 L0 计划阶段读取：同资产最近 3 条记录 + 跨资产最近 5 条 reflection，注入对应分析师的 prompt（不是全局注入，避免污染）。

这一套替代 RAG 的 L3 沉淀，且比它强的地方在于：**可结算、可归因、可校准**。

## 5. 关键机制细节

### 5.1 EvidenceLedger

```python
class EvidenceItem(BaseModel):
    evidence_id: str                  # EV-0001，任务内单调递增
    asset_id: str
    category: Literal["price","technical","valuation","fundamental",
                      "news","announcement","macro","policy","flow"]
    statement: str                    # 一句话事实，不含判断
    value: float | str | None = None
    unit: str = ""
    caliber: str = ""                 # "PE(TTM)" / "前复权" / "单季"
    source_tool: str
    source_url: str = ""
    source_time: str = ""             # 数据自带时间（公告日/交易日）
    retrieved_at: str
    confidence: float = 0.8
    raw_ref: str = ""                 # tool_call_id，用于回放
```

写入时机：**不是让模型输出 `[FINDINGS]`**，而是在 `loop._execute_tool` 成功后由代码自动登记。模型额外声明的证据可以覆盖 `statement` 字段（更简洁），但 `value/source/time` 以工具返回为准。

去重：`(asset_id, category, normalized(statement))` 完全一致则合并，保留最新 `retrieved_at` 并累加 `seen_count`。

Ledger 是唯一允许被下游引用的证据来源。任何不在 Ledger 里的数字，Verifier 一律判为 invalid。

### 5.2 为什么这解决"信息孤岛"

- 分析师之间不再通过自然语言池子交流，而是共同写入一个结构化台账。
- 后启动的分析师（或补派的分析师）能直接看到已有哪些证据、哪些问题还没答，避免重复调同一个工具（现在三路会各调一次行情）。
- 下游 Bull/Bear 拿到的是同一份事实集，分歧只可能来自推理，不可能来自"各看各的数据"。

### 5.3 防谄媚的四个具体设计

1. **独立建论**：Bull/Bear 并行生成，prompt 中不含对方任何输出。
2. **盲判基线**：裁判先只看证据出结论，辩论记录后置。
3. **零让步成本**：整轮零让步触发额外核查，逼迫真实评估而不是姿态性坚持。
4. **攻击类型受限**：不允许"我觉得你的逻辑有问题"这种空泛攻击，必须落到六类之一并给出举证形式。

### 5.4 预算与超时

| 阶段 | LLM 调用 | 并行度 | 工具预算 | 超时 |
|---|---|---|---|---|
| L0 Supervisor | 1 | 1 | 1（资产解析） | 30s |
| L1 分析师 ×4 | 4 × (2-4 轮) = 8-16 | 4 | 每路 6 | 每路 180s |
| L2 Thesis ×2 | 2 | 2 | 每方 0-1 | 90s |
| L3 Debate | 4 | 2（同方串行） | 每方 1（仅 R1） | 每轮 90s |
| L4 Judge | 2（盲判+裁决） | 1 | 0-1 | 120s |
| L5 Verifier | 1-2 | 1 | 0-1 | 90s |
| L6 结算 | 0（下次任务） | 1 | 1 | 60s |
| **合计** | **18-27** | — | **≤ 32** | 任务级 10 分钟硬超时 |

对比现状：现状是 3 路 × 最多 8 轮 + 第二轮 3 轮 + 总结 8 轮 ≈ 35-40 次调用，且无超时。新框架调用量持平或更低，但每阶段都有预算和超时。

实现要点：

- 用 `ThreadPoolExecutor(max_workers=4)` 跑 L1，`future.result(timeout=...)` 必须带超时。
- 每个 stage 通过同一个 `Budget` 对象扣减，扣到 0 后该 Agent 强制收敛（不是抛异常）。
- 任务级 watchdog：超时则输出已完成阶段的部分结果，标记 `partial=true`。

## 8. 工具与数据补齐（前置条件）

这是本方案能否成立的分水岭。按 P0 / P1 排序：

### P0-1 新闻多源 + 去锁 + 缓存

现状问题：`utils/web_search.py:17` 全局 `_SEARCH_LOCK`，排队 15s 超时返回空；无缓存；结果被当成"无新闻"。

改造：

- 拆成 `providers/` 多源：东财新闻、新浪财经、巨潮公告、ddgs 网页搜索（作为兜底），每源独立超时。
- 锁粒度从"全局"降到"单 provider 单 host"，或直接用连接池 + 信号量限流。
- 加二级缓存：`(query, 源) -> 结果`，TTL 按源区分（新闻 10 分钟，公告 1 小时）。
- 返回结构补齐 `published_at / source_domain / url`，否则无法做时效性校验。

### P0-2 财务数据（tushare 优先）

**先做 capability probe**（`src/data/probe.py`）：启动时逐接口探测可用性，结果缓存到 `src/data/capabilities.json`。工具层按探测结果选源，不靠硬编码假设。

- 首选 tushare：`income` / `balancesheet` / `cashflow` / `fina_indicator` / `daily_basic`。tushare 有 `ann_date`（公告日），这是回测做 point-in-time 的必需字段。
- 降级 akshare：`stock_financial_abstract`（财务摘要）、`stock_financial_analysis_indicator`（财务指标）、`stock_financial_report_sina`（三大报表）。字段口径不统一，仅作兜底。
- `ToolResult` 增加 `data_source` 字段，前端与报告标注实际来源。

必须产出的字段（否则基本面分析师无意义）：营收/营收增速、归母净利/增速、毛利率、净利率、ROE、经营现金流、资产负债率、应收账款周转、存货周转。至少 8 个季度时序，且必须带公告日。

### P0-3 公告

tushare `anns_d` 优先（若权限可用），降级 akshare `stock_notice_report`。这是事件驱动研究的核心输入，缺失会让 NewsAnalyst 只能靠搜索摘要猜测。公告必须带 `ann_date`，否则回测模式禁用。

### P1-1 资金与筹码

tushare `moneyflow`（主力净流入）、`top_list` / `top_inst`（龙虎榜）、`top10_holders` / `stk_holdernumber`（股东与户数）；不可用时降级 akshare `stock_individual_fund_flow` / `stock_lhb_detail_em` / `stock_zh_a_gdhs`。用于"资金面"证据类别。

### P1-2 同业对比

按行业拉取同业的 PE/PB/ROE/增速，产出分位数。这是"估值贵不贵"唯一靠谱的依据，单看 PE 绝对值没有意义。

### P1-3 宏观

tushare `cn_pmi` / `cn_cpi` / `cn_gdp` / `shibor` / `lpr` / `bond_zh_us_rate` 优先，降级 akshare `macro_china_pmi` / `macro_china_cpi` / `macro_china_lpr`。MacroAnalyst 需要可引用的数字，而不是新闻里的措辞。

### P1-4 技术指标补齐

MACD / RSI / KDJ / 布林 / 成交量分位。现在只有 MA，技术分析师能说的话非常有限。

## 10. 实施路径

### 阶段 0：清场与地基（必须先做）

1. 删除 RAG（§7 全清单），验证 `create_app()` 可启动、import 时间下降。
2. 新闻多源改造（§8 P0-1）。这是并行取证能否工作的前提。
3. 建 `EvidenceLedger` + `state.py` 新模型 + 单元级自测（去重、引用、序列化）。
4. 建 `Budget` 与 `pipeline.py` 的阶段执行骨架（超时、并行、预算扣减）。

验收：四个分析师能以假数据并行跑完，Ledger 有结构化证据，任务级超时生效。

### 阶段 1：取证层替换

1. 四个分析师 Agent + 新 prompt（只交证据）。
2. `loop.py` 工具结果自动登记 Ledger；删除共享池全部逻辑。
3. Supervisor 输出 `ResearchPlan`，按 plan 并行调度分析师。
4. 前端接 `phase_*` 与 `evidence_added`。

验收：同一问题，报告里每个数字都能点回 `evidence_id` 与 `source_url`；分析师输出中不含结论词；超时与单路失败不影响其他路。

### 阶段 2：论点与辩论

1. `Thesis` / `Claim` 模型与生成逻辑（Bull/Bear 并行、互不可见）。
2. `debate.py`：两轮协议、攻击类型校验、零让步检测、停止条件。
3. 前端 `thesis_submitted` / `debate_turn`。

验收：人为构造"一边证据明显更强"的案例，弱方必须出现 `concede` 或明确的 `no_concession_reason`；辩论不引入 Ledger 外事实。

### 阶段 3：裁决与质检

1. 盲判 + 终判两段调用，`revision_reason` 必填。
2. `verifier.py` 机械校验（引用/数字/口径/时效/合规）+ LLM 校验（focus_questions、逻辑跳跃、风险低估）。
3. 有界回退（最多 1 次/类）。

验收：注入"引用不存在的 evidence_id"与"数字被模型改写"两个故障，Verifier 都能拦截并触发重写；合规词命中直接阻断。

### 阶段 4：闭环

1. `DecisionRecord` 落 SQLite；`decision_id` 返回前端。
2. 结算：到期记录拉取区间收益与 alpha，生成 reflection。
3. 反思注入：L0 计划阶段按资产/行业检索最近记录，注入对应分析师。

验收：构造一条 30 天前的记录，结算能算出收益与 alpha；新任务能读到该 reflection 并体现在分析师 prompt 中。

### 阶段 5：数据补齐与校准（可与 3、4 并行）

1. 财务 / 公告 / 同业 / 宏观工具（§8），全部走 tushare 优先 + capability probe。
2. 置信度校准：统计 verdict conviction 分桶的实际命中率，输出校准曲线；偏差超过阈值则调整 prompt 中的锚点。

### 阶段 6：回测与校准系统

详细设计见 `docs/投研智能体框架-决策记录与回测设计.md` 第三部分。实施顺序：

1. `backtest/clock.py`（交易日历、T+1、停牌/涨跌停、持有期）+ 纯逻辑测试。
2. `backtest/datasource.py`（as_of 过滤，`PIT_MODE` 断言）+ `universe.py`（历史成分股）。
3. `backtest/runner.py`（决策点遍历、幂等、断点续跑）+ `cache.py`（LLM 响应缓存）。
4. `backtest/metrics.py`（hit / alpha / Brier / calibration / ablation）+ `report.py`。
5. 先跑 20-30 点 pilot，再按需扩到 100 点以上。

验收：同一 `run_id + asset + as_of` 重跑走缓存且数值一致；注入未来数据时 PIT 断言抛错；前复权收益与手工核对误差 < 0.01%；新闻类证据在回测中全部标记 `unavailable`。

## 11. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 辩论退化为表演 | 双方互相夸、快速共识 | 独立建论 + 盲判 + 零让步成本 + 攻击类型约束 |
| 裁判被锚定 | 终判等于首轮立场 | 盲判留档，统计 blind vs final 的偏离率；偏离率长期为 0 说明辩论无效 |
| 证据通胀 | Ledger 堆满低价值事实，context 爆炸 | 按 category 配额（每类 ≤ 12 条）+ 重要性排序，注入时只取 top-N |
| 分析师空转 | 工具缺失导致反复重试 | 预算扣减 + 连续 2 次无新增证据即收敛 + `gaps` 显式记录 |
| 成本上升 | 18-27 次调用 | 快慢模型分层（分析师/辩论用快模型，Judge 用深模型）；`debate` 按争议度触发；预算硬上限 |
| 数据时点错误 | 用未来数据回测 | PIT 由数据层强制（`as_of` 过滤 + `PIT_MODE` 断言）；财务按 `ann_date` 过滤；无时间戳的新闻源在回测中禁用；历史成分股防幸存者偏差 |
| 回测自欺 | 只报好看的参数组合、用当前成分股、当日收盘决策当日成交 | 报告必须列全部参数组合；`universe_bias` 样本不计入汇总；强制 T+1 开盘成交；不稳定样本单列 |
| 结论无增量 | 报告看起来严谨，但没有新信息 | 量化 `evidence_citation_density` / `claim_coverage` / `debate_increment`，任一低于阈值标注"低增量" |
| 单进程状态 | 多 worker 下 SSE 丢失 | 维持单 worker 部署（现状即如此），在 README 写明；未来若要扩，event_bus 换 Redis |
| 合规 | 输出确定性买卖指令 | Verifier 词表阻断 + Verdict 只允许仓位区间表述 |

## 13. 附录

### A. 分析师 prompt 骨架（共性部分）

```
【角色】
你是 {role}，负责 {evidence_scope}。

【输出要求】
1. 只输出事实性证据，禁止输出"看多/看空/建议/目标价"等结论。
2. 每条证据必须可回溯：写明数值、单位、口径、数据时间。
3. 无法回答的问题写入 gaps，不要用推测填补。
4. 工具返回失败时，记录到 gaps 并说明失败原因，不要重复调用同一工具超过 2 次。

【取证顺序】（按价值排序，不是必须全部执行）
{ordered_questions}

【证据标准】
- 优先取近 {freshness} 内的数据；超期数据必须标注时效。
- 同一指标只取一个口径，跨口径对比必须显式说明。
- 与已有证据冲突时，两条都保留并标注 conflict，不要自行裁决。
```

### B. 辩论 prompt 骨架（R1 Attack）

```
你是 {side} 方研究员。以下是对方最强的前 2 条主张：

{opponent_claims}

请对每条主张发起一次攻击。攻击必须属于以下六类之一，并给出对应举证：
evidence_gap / logic / caliber / timing / base_rate / priced_in

禁止：
- 引入证据台账之外的新事实（需要新证据请调用工具，本次仅允许 {n} 次）。
- 空泛评价（"论证不充分"）而不指出具体缺口。
- 攻击对方语气或立场，只攻击论证本身。

输出 JSON：
{"attacks": [{"target_claim_id": "...", "attack_type": "...",
             "argument": "...", "cited_evidence_ids": ["..."]}]}
```

### C. 辩论 prompt 骨架（R2 Defend / Concede）

```
你在上一轮被如下攻击。对每条被攻击的主张，三选一作答：
- defend：说明攻击不成立，必须引用证据或补充推理
- revise：下调 strength 或修正表述，说明改了哪里
- concede：撤回该主张，说明为什么

全局要求：若你本轮零让步，必须在 no_concession_reason 中说明理由（不少于 150 字），
并会被额外核查。真正的对抗不等于死守，也不等于轻易投降。
```

### D. Judge prompt 关键句

```
【盲判阶段】
你只能看到证据台账与两份匿名论点。不要尝试猜测哪份来自哪一方。
给出你的独立判断：stance / conviction / 关键驱动 / 最大不确定性。

【裁决阶段】
你现在看到完整辩论记录。最终判断可以与盲判不同，但必须在 revision_reason 中
写明：哪一条攻击或让步改变了你的判断，为什么它比原判断更有说服力。
若判断未变，说明辩论为何没有提供新信息。

禁止：
- 因双方"都有道理"而默认中性。中性必须区分"证据真对冲"与"关键数据缺失"。
- 引用任何未出现在证据台账中的数字。
```

### E. 验收用例（建议）

| 用例 | 预期行为 |
|---|---|
| 单票、证据充分、方向明确 | 辩论 1 轮即收敛；弱方让步；Verdict 与盲判一致，`revision_reason` 说明"无新信息" |
| 单票、关键财务数据缺失 | 基本面分析师 `gaps` 非空；Verifier 标记 `needs_data`；Verdict 置信度 < 0.6 |
| 新闻与价格背离 | 争议度高，触发辩论；分歧矩阵出现 `needs_data` 条目 |
| 工具大面积失败 | 任务级降级，报告顶部标注；不产出高置信度结论 |
| 模型编造证据 ID | Verifier 拦截，回退重写 1 次，仍失败则降级 |
| 合规词 | 直接阻断并改写 |

## 附：本方案的取舍说明

- **没有引入 LangGraph / AutoGen / CrewAI**。现有同步线程池 + ReAct 循环已够用，引入框架会带来依赖与调试成本，且当前瓶颈在信息结构，不在编排能力。
- **没有做人格化 Agent**。人格 prompt 产出不可证伪的叙事，与"严谨"目标冲突。
- **没有做向量记忆**。结构化记录 + SQLite 查询在投研场景可解释性远高于 embedding 召回，且可结算、可校准。
- **没有做多轮自由辩论**。研究一致表明 2 轮之后边际信息趋近于零，成本却线性增长。
