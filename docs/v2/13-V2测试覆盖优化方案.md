# V2 测试覆盖优化方案

> 基于当前测试盘点、V2 可演示闭环修复过程，以及注册接口 400 问题暴露出的测试缺口整理。

## 1. 目标

本方案目标是把测试体系从“有一些测试文件”推进到“能稳定拦住演示主路径回归”。

重点覆盖链路：

1. 注册 / 登录 / 获取用户信息
2. 进入 V2 研究工作台前的基础 API 客户端
3. V2 查询提交、任务状态、SSE 事件流
4. 前端对成功态、失败态、SSE 兜底、历史 turn 的渲染
5. 关键错误场景：401、400、404、后端不可达、任务失败、任务超时

本阶段不追求完整生产级测试矩阵，优先补齐“演示闭环”和“入口链路”的硬性 smoke 测试。

## 2. 当前测试现状

### 2.1 已有测试类型

当前仓库已有以下测试：

- `tests/`
  - API 端点测试
  - 集成测试
  - E2E / Playwright 测试
  - 前端组件测试
- `src/agent/test/`
  - V2 asset resolver
  - V2 graph
  - V2 planner / registry / executor
  - V2 evidence / answer / memory
  - V2 eval / safety / reliability
  - task service
- `src/web/src/__tests__/`
  - App 基础渲染
  - V2 API service
  - feedback system
- `src/news/test/`、`src/stock/test/`、`src/utils/test/`
  - 数据源与工具类测试

### 2.2 当前运行结果

近期验证结果：

- `cd src/web && npm test -- --run`
  - 19 passed
- `python -m pytest src/agent/test/test_v2_api_task_service.py src/agent/test/test_v2_graph.py src/agent/test/test_v2_planner_registry_executor.py src/agent/test/test_v2_evidence_answer_memory.py -q`
  - 16 passed
- `python -m pytest tests -q`
  - 1 failed
  - 6 errors

### 2.3 结构性问题

`pytest.ini` 当前配置：

```ini
[pytest]
testpaths = tests
python_files = test_*.py
python_classes = Test*
python_functions = test_*
asyncio_mode = auto
```

这意味着默认 `python -m pytest` 只会跑 `tests/`，不会自动跑到：

- `src/agent/test/`
- `src/news/test/`
- `src/stock/test/`
- `src/utils/test/`

因此，V2 核心测试虽然存在，但不在默认测试集合里。

## 3. 主要缺口

### 3.1 认证接口测试过于宽松

当前 `tests/test_api_endpoints.py` 里的注册测试允许：

```python
assert response.status_code in [200, 201, 400, 500]
```

这类断言无法证明功能可用。注册接口返回 400 或 500 时测试仍可能通过，导致真实入口问题无法被拦住。

**影响：**

- `POST /api/auth/register` 请求体错误不会被测试发现。
- 注册 / 登录 / profile 的完整入口链路没有硬性验收。
- 浏览器手测前仍可能卡在登录注册阶段。

### 3.2 前端通用 API 客户端缺少测试

当前 `apiV2Service.js` 有 Vitest，能验证 V2 请求体被序列化。

但真实暴露问题的是 `src/web/src/services/apiClient.js`：

- `register()`
- `login()`
- `fetchProfile()`
- `updateProfile()`
- `updatePhone()`

这些通用 API 没有单元测试覆盖。之前 `apiClient.request()` 把普通对象直接传给 `fetch body`，浏览器发出了不可解析的 `"[object Object]"`，测试没有拦住。

### 3.3 E2E / Playwright 测试当前不可用

`tests/test_frontend_components.py` 当前会报：

```text
RuntimeError: This event loop is already running
```

原因是 pytest-asyncio 环境中，fixture 内部又调用了 `run_until_complete()`。

另外，该文件存在占位测试：

```python
pass
```

这类测试不会验证真实行为。

### 3.4 Live API 测试依赖外部服务状态

`tests/` 下多处测试依赖已经启动的后端和前端：

- 默认后端端口：`5001`
- 默认前端端口：`5173`

这类测试适合作为 smoke test，但不适合作为稳定单元 / 集成测试。它们容易受旧进程、端口占用、本地数据库状态影响。

### 3.5 V2 可演示闭环缺少端到端 smoke

当前没有一条测试完整覆盖：

1. 注册
2. 登录
3. 获取 profile
4. 提交 V2 query
5. 获取 task status
6. 订阅 SSE events
7. 校验事件类型
8. 校验最终结果结构

因此，接口级联调只能靠手工 curl 或浏览器观察。

### 3.6 前端研究工作台关键状态缺少测试

当前缺少对以下前端行为的自动化覆盖：

- SSE 事件驱动节点状态变化
- 工具卡片从 running 到 completed / failed
- `task_completed` 与轮询同时返回时不会重复归档 turn
- 完成态历史 turn 使用最新 agents / tools / evidence 快照
- 任务失败时展示错误信息
- 后端不可达时展示错误信息
- 404 时提示 V2 未启用

## 4. 优化原则

### 4.1 分层测试，不混用目标

建议将测试分为四层：

1. **纯单元测试**
   - 不启动后端
   - 不访问数据库
   - 不依赖网络
   - 适合测试前端 service、工具函数、状态转换

2. **后端集成测试**
   - 使用 Flask test client 或隔离数据库
   - 不依赖已启动外部服务
   - 适合注册、登录、profile、V2 query 参数校验、401 / 400 / 404

3. **接口 smoke 测试**
   - 允许依赖已启动后端
   - 只验证演示主路径是否可用
   - 适合浏览器手测前执行

4. **浏览器 E2E 测试**
   - 使用 Playwright
   - 访问真实前端
   - 验证 UI 关键状态和用户流程

### 4.2 入口链路必须硬断言

以下接口不能再允许宽松状态码：

- 注册成功必须是 `201`
- 登录成功必须是 `200`
- profile 成功必须是 `200`
- 未授权 profile 必须是 `401`
- V2 query 未授权必须是 `401`

如果测试用户已存在，应使用唯一用户名，而不是允许 400。

### 4.3 Smoke 测试可以依赖服务，但必须显式端口

Smoke 测试必须允许通过环境变量指定：

- `FLASK_PORT`
- `VITE_PORT`
- `VITE_API_BASE_URL`

不要隐式假设一定是 `5001` / `5173`。

## 5. 建议新增和修改的测试

### 5.1 修正默认 pytest 覆盖范围

**问题：**

默认 `pytest` 只跑 `tests/`。

**修改方向：**

将 `pytest.ini` 调整为：

```ini
[pytest]
testpaths =
    tests
    src/agent/test
    src/news/test
    src/stock/test
    src/utils/test
python_files = test_*.py
python_classes = Test*
python_functions = test_*
asyncio_mode = auto
```

**注意：**

如果某些数据源测试依赖外网或第三方服务，应加 marker，例如：

```ini
markers =
    smoke: requires running local backend/frontend
    external: requires network or third-party data source
    slow: long-running tests
```

然后默认测试排除 `external` 和 `slow`：

```bash
python -m pytest -m "not external and not slow"
```

### 5.2 硬化认证接口测试

**目标：**

确保注册、登录、profile 三步入口链路可用。

**建议文件：**

- `tests/test_auth_flow.py`

**测试用例：**

1. `test_register_returns_201_and_token`
   - 使用时间戳生成唯一用户名和邮箱。
   - 调用 `POST /api/auth/register`。
   - 断言：
     - status code 为 `201`
     - 返回 `token`
     - 返回 `user.username`

2. `test_login_returns_200_and_token_after_register`
   - 先注册。
   - 再登录。
   - 断言：
     - status code 为 `200`
     - 返回 `token`

3. `test_profile_requires_auth`
   - 不带 token 调用 `/api/user/profile`。
   - 断言 status code 为 `401`。

4. `test_profile_returns_user_with_valid_token`
   - 注册拿 token。
   - 带 token 调用 `/api/user/profile`。
   - 断言：
     - status code 为 `200`
     - 返回 username / email / user_tier / quota。

**验收标准：**

注册接口返回 400 / 500 时测试必须失败。

### 5.3 补充前端 `apiClient.js` 单元测试

**目标：**

防止再次出现请求体未 JSON 序列化的问题。

**建议文件：**

- `src/web/src/__tests__/apiClient.test.js`

**测试用例：**

1. `register serializes request body`
   - mock `fetch`
   - 调用 `register(username, password, email)`
   - 断言 `fetch` 的 `body` 是字符串
   - `JSON.parse(body)` 后等于预期对象

2. `login serializes request body`
   - 同上，验证 login body。

3. `updateProfile serializes request body`
   - 验证 PUT body。

4. `fetchProfile sends authorization header when token exists`
   - 设置 token
   - 调用 `fetchProfile()`
   - 断言 header 有 `Authorization: Bearer ...`

5. `register surfaces backend validation error`
   - mock 400 `{error: "用户名或邮箱已存在"}`
   - 断言抛出对应错误。

**验收标准：**

如果 `apiClient.request()` 再次把对象原样传给 `fetch body`，测试必须失败。

### 5.4 补充 V2 接口 smoke 测试

**目标：**

浏览器手测前，用一个命令确认后端主路径可用。

**建议文件：**

- `tests/test_v2_smoke.py`

**测试前提：**

要求本地后端已启动，并设置：

```bash
AGENT_V2_ENABLED=true
FLASK_PORT=5004
```

运行：

```bash
FLASK_PORT=5004 python -m pytest tests/test_v2_smoke.py -v
```

**测试用例：**

1. `test_v2_health_enabled`
   - `GET /api/agent/v2/health`
   - 断言 `v2_enabled is True`

2. `test_v2_query_requires_auth`
   - 不带 token 调用 `POST /api/agent/v2/query`
   - 断言 `401`

3. `test_v2_submit_query_returns_task_id`
   - 注册 / 登录拿 token
   - 调用 `POST /api/agent/v2/query`
   - 断言返回 `task_id`、`session_id`、`status`

4. `test_v2_status_returns_result_shape`
   - 轮询 `GET /api/agent/v2/status/<task_id>`
   - 最终断言：
     - `result.critic_result` 存在
     - `result.compliance_result` 存在
     - `result.investment_answer` 存在或 `degraded=True`
     - `investment_answer.scenarios` 为数组

5. `test_v2_sse_emits_expected_events`
   - 提交 query 后连接 `/events/<task_id>?token=...`
   - 读取事件流。
   - 断言至少收到：
     - `task_started`
     - `node_started`
     - `node_completed`
     - `tool_started`
     - `tool_completed`
     - `evidence_added`
     - `draft_created`
     - `critic_completed`
     - `compliance_completed`
     - `task_completed`

**验收标准：**

接口层联调不再靠人工描述，而是可重复执行。

### 5.5 修复或替换 Playwright 测试

**问题：**

`tests/test_frontend_components.py` 当前 fixture 写法会导致事件循环错误。

**修改方向 A：改为同步 Playwright**

复用 `tests/test_e2e.py` 的同步写法：

```python
from playwright.sync_api import sync_playwright
```

不要在 async fixture 里调用 `run_until_complete()`。

**修改方向 B：改为纯 pytest-asyncio**

如果继续用 async Playwright，则 fixture 必须改成 async fixture，并交给 pytest-asyncio 管理。

建议短期选择方向 A，减少复杂度。

**同时删除或实现占位测试：**

- `test_toast_notification`
- `test_loading_state`

不能保留只有 `pass` 的测试。

### 5.6 新增研究工作台前端状态测试

**目标：**

验证 React UI 对 V2 事件的消费逻辑。

**建议文件：**

- `src/web/src/__tests__/ResearchChatView.test.jsx`

**测试策略：**

mock `apiV2Service`：

- `submitQuery()` 返回 `{task_id, session_id}`
- `createEventStream()` 立即按顺序触发事件
- `getTaskStatus()` 作为轮询兜底 mock

**测试用例：**

1. `renders running nodes from SSE events`
   - 触发 `node_started`
   - 断言对应 Agent 显示运行中。

2. `renders completed tool card`
   - 触发 `tool_started` / `tool_completed`
   - 断言工具卡片显示完成。

3. `deduplicates task completion from SSE and polling`
   - SSE 和 polling 都返回 completed。
   - 断言历史 turn 只新增一条。

4. `archives latest evidence and tools into completed turn`
   - 先触发 evidence 和 tool events。
   - 再触发 task_completed。
   - 折叠 / 展开历史 turn 后仍能看到证据和工具。

5. `shows error message when query fails`
   - mock `submitQuery()` reject。
   - 断言页面显示错误提示。

6. `shows v2 disabled message on 404`
   - mock API 抛出 V2 未启用错误。
   - 断言提示文案。

**验收标准：**

这组测试必须能防住：

- SSE / polling 双完成重复归档
- 完成态闭包拿旧 state
- 错误态静默

### 5.7 标记 live smoke 测试

**目标：**

避免默认测试被本地端口和服务状态污染。

**建议：**

给依赖真实后端 / 前端的测试加：

```python
@pytest.mark.smoke
```

例如：

- `tests/test_api_endpoints.py`
- `tests/test_integration.py`
- `tests/test_e2e.py`
- `tests/test_frontend_components.py`

默认本地单元测试：

```bash
python -m pytest -m "not smoke and not external and not slow"
```

手动 smoke：

```bash
FLASK_PORT=5004 VITE_PORT=5174 python -m pytest -m smoke -v
```

## 6. 推荐执行顺序

### P0：立刻补齐

1. 修复 `tests/test_frontend_components.py` 的 Playwright fixture。
2. 删除或实现 `pass` 占位测试。
3. 补 `src/web/src/__tests__/apiClient.test.js`。
4. 把注册 / 登录 / profile 测试改成硬断言。
5. 新增 `tests/test_v2_smoke.py`。

### P1：稳定默认测试集

1. 调整 `pytest.ini` 覆盖范围。
2. 增加 pytest markers。
3. 将依赖真实服务的测试标记为 `smoke`。
4. 整理测试命令：
   - 单元测试
   - V2 核心测试
   - 前端单元测试
   - live smoke 测试

### P2：增强 UI 行为测试

1. 新增 `ResearchChatView.test.jsx`。
2. mock SSE 事件流。
3. 覆盖完成态归档、错误态、轮询兜底。
4. 后续再接入 Playwright 做真实浏览器流程。

## 8. 完成定义

测试覆盖优化完成后，应满足：

- `apiClient.js` 的 JSON 序列化有单元测试保护。
- 注册、登录、profile 接口有硬断言测试。
- V2 query / status / SSE / result shape 有 live smoke 测试。
- Playwright 测试可以正常运行，不再出现事件循环错误。
- 测试中没有空 `pass` 占位。
- 默认 pytest 不会漏掉 V2 核心测试，或通过明确命令区分测试层级。
- 浏览器手测前有一条固定 smoke 命令可跑。

达到以上标准后，类似“注册接口 400 但测试没发现”的问题应能在手测前被自动拦截。
