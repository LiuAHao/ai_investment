# 01 - V2 基础架构与迁移边界

## 目标

本阶段目标是在不破坏 V1 功能的前提下，搭建 V2 的基础代码骨架、数据结构、接口边界和迁移策略。

V2 不应直接替换现有 `MasterAgent`，而是以并行能力存在：

- V1 继续服务当前前端和已有接口。
- V2 新增独立目录、独立 API、独立状态模型。
- 后续通过配置或前端入口逐步切换。

## V1 与 V2 边界

### V1 保留内容

以下模块第一阶段不删除、不重构，只作为 V2 的底层能力复用：

- `src/agent/master_agent.py`
- `src/agent/data_agent.py`
- `src/agent/news_agent.py`
- `src/agent/knowledge_agent.py`
- `src/agent/analysis_agent.py`
- `src/api/agent.py`
- 当前前端分析入口

### V2 新增内容

V2 新增：

- 独立状态模型 `InvestmentState`。
- 独立图编排 `graph.py`。
- 独立 API：`/api/agent/v2/query`、`/api/agent/v2/status`。
- 独立工具注册中心。
- 独立评测体系。

## 配置项

建议在 `.env.example` 增加：

```text
AGENT_V2_ENABLED=false
AGENT_V2_DEFAULT=true
AGENT_V2_DEBUG=false
AGENT_V2_MAX_ITERATIONS=6
AGENT_V2_TOOL_TIMEOUT=20
AGENT_V2_REQUIRE_CRITIC=true
AGENT_V2_REQUIRE_COMPLIANCE=true
```

含义：

- `AGENT_V2_ENABLED`：是否开启 V2 API。
- `AGENT_V2_DEFAULT`：前端是否默认走 V2。
- `AGENT_V2_DEBUG`：是否返回详细 Agent trace。
- `AGENT_V2_MAX_ITERATIONS`：ReAct 循环最大次数。
- `AGENT_V2_TOOL_TIMEOUT`：单个工具超时时间。
- `AGENT_V2_REQUIRE_CRITIC`：是否强制 Critic 校验。
- `AGENT_V2_REQUIRE_COMPLIANCE`：是否强制合规校验。

## 第一阶段 Schema

最小可用 Schema：

```python
class InvestmentState(BaseModel):
    session_id: str
    user_id: int
    query: str
    chat_history: List[Dict[str, str]] = []
    user_profile: Dict[str, Any] = {}
    intent: Optional[IntentResult] = None
    assets: List[Asset] = []
    plan: Optional[ExecutionPlan] = None
    tool_results: List[ToolResult] = []
    evidence_items: List[EvidenceItem] = []
    draft_answer: Optional[str] = None
    final_answer: Optional[str] = None
    degraded: bool = False
    errors: List[str] = []
    trace: List[Dict[str, Any]] = []
```

第一阶段可以先让部分字段为空，但字段要提前设计好，避免后续大改接口。

## API 边界

### 新增查询接口

```text
POST /api/agent/v2/query
```

职责：

- 校验用户身份。
- 校验 query 长度。
- 创建或复用 session_id。
- 初始化 V2 状态。
- 启动 V2 图执行。
- 返回 task_id 和 session_id。

### 新增状态接口

```text
GET /api/agent/v2/status/{task_id}
```

职责：

- 返回任务状态。
- 返回当前节点。
- 返回进度。
- 返回部分工具结果。
- 返回最终结果。

## 验收标准

完成本阶段后应满足：

- V1 所有原接口可继续使用。
- V2 API 可以独立启动。
- V2 能返回结构化状态。
- V2 可以调用现有 V1 Agent 能力。
- 出现 V2 异常时不影响 V1。

## 风险点

- 不要在第一阶段重写所有 Agent。
- 不要一次性迁移前端。
- 不要把 V2 状态和 V1 数据结构混在一起。
- 不要让 V2 失败直接影响现有 `/api/agent/query`。

## 推荐开发步骤

1. 新增目录骨架。
2. 新增 Pydantic Schema。
3. 新增 V2 API 蓝图。
4. 在 `src/api/main.py` 注册 V2 蓝图。
5. 新增 V2 graph 最小实现。
6. 复用现有 Agent 跑通单次查询。
7. 增加最小状态查询。
