# 04 - 工具注册中心与工具适配器

## 目标

本阶段目标是建立 Tool Registry，让 Planner 不再硬编码调用某个 Agent，而是根据意图、资产类型和数据需求选择工具。

工具注册中心解决三个问题：

- 工具发现：系统有哪些工具可用。
- 工具选择：当前问题应该调用哪些工具。
- 工具治理：工具输入输出、超时、失败、回退、数据新鲜度如何统一管理。

## ToolSpec 模型

```python
class ToolSpec(BaseModel):
    name: str
    description: str
    input_schema: Dict[str, Any]
    output_schema: Dict[str, Any]
    asset_types: List[str]
    intents: List[str]
    cost_level: Literal["low", "medium", "high"]
    timeout_seconds: int
    freshness_requirement_seconds: Optional[int]
    fallback_tools: List[str] = []
    risk_level: Literal["low", "medium", "high"] = "low"
```

## ToolResult 模型

```python
class ToolResult(BaseModel):
    tool_name: str
    status: Literal["success", "failed", "skipped", "partial"]
    asset_id: Optional[str]
    data: Dict[str, Any]
    source: Optional[str]
    source_url: Optional[str]
    data_timestamp: Optional[datetime]
    fetched_at: datetime
    freshness_seconds: Optional[int]
    confidence: float
    error: Optional[str]
    latency_ms: int
```

## 工具执行约束

每次工具调用必须：

- 校验输入。
- 设置超时。
- 捕获异常。
- 返回 ToolResult。
- 不直接向用户暴露错误堆栈。
- 记录 tool_calls。

## 回退策略

示例：

```text
cn_stock_history 失败
  ↓
cn_stock_history_tx
  ↓
cn_stock_daily_sina
  ↓
返回 partial，并在数据限制中说明行情数据不可用
```

当前 DataAgent 已有类似 fallback，V2 应把 fallback 信息结构化记录到 ToolResult。

## 数据新鲜度

不同工具要求不同：

```text
实时行情：15 分钟以内
新闻：24 小时以内
基金净值：1-2 个交易日内
财务数据：一个报告期内
RAG 知识：可长期有效，但需要版本号
宏观指标：取决于指标发布频率
```

如果数据过旧：

- ToolResult 标记 `confidence` 降低。
- EvidenceItem 增加 limitation。
- 最终答案必须说明数据时效性限制。

## 验收标准

- Planner 不直接调用 DataAgent，而是通过 Tool Registry 找工具。
- 所有工具返回统一 ToolResult。
- 工具失败不会导致整体任务崩溃。
- 工具调用能记录到数据库或 trace。
- 不同资产类型能匹配不同工具。
