# AI投资分析系统 V2 前端重构设计方案

## 1. 文档目标

本文档用于交接给前端设计人员，作为 AI 投资分析系统 V2 前端重构的设计依据。

V2 前端不再采用传统“三栏后台式工作台”，而是采用更具产品感的“纵向研究线程”形态：

```text
大输入首屏
  ↓
主问题分析流程
  ↓
完整 Agent 工作流过程
  ↓
结构化分析结论
  ↓
追问输入
  ↓
追问分析流程继续追加
  ↓
追问补充结论
  ↓
继续追问，形成无限延展研究线程
```

整体目标是让用户感觉自己不是在使用一个普通聊天机器人，而是在使用一个“可观察、可追问、可沉淀”的 AI 投资研究 Agent。

## 2. 产品定位

V2 前端定位为：

> 一个面向投资研究场景的 AI Agent 过程可视化页面。

核心特征：

- 用户从一个大输入框开始研究。
- AI 的分析过程通过 SSE 实时展示。
- 每个 Agent 都有清晰的工作状态和阶段输出。
- 工具调用、证据池、风险校验、合规校验都能被用户看到。
- 最终结果以研究报告形式呈现。
- 用户可以围绕同一研究主题持续追问。
- 每一次追问都会继续追加到当前页面，形成一个无限迭代的研究线程。

## 3. 需要保留的页面

### 3.1 首页

保留首页，但需要升级为 V2 产品入口。

首页目标：

- 展示品牌。
- 引导用户进入 AI 投资研究。
- 强调 V2 的“过程可视化、证据链、多轮追问、合规分析”能力。

建议核心文案方向：

```text
AI 投资研究 Agent
让每一次分析都有过程、有证据、有风险边界
```

首页保留：

- Logo。
- 登录按钮。
- 注册按钮。
- 主要 CTA：开始研究。

### 3.2 登录与注册

保留现有登录/注册能力。

要求：

- 保持现有红黑风格。
- 保留用户名、邮箱、密码注册。
- 保留登录后进入主研究页。
- 错误提示保持清晰。

### 3.3 主研究页

这是 V2 的核心页面，需要重点重构。

主研究页不是传统三栏页面，而是一个纵向展开的研究线程页面。

### 3.4 个人中心与设置

保留现有个人中心和设置页。

建议新增或强化以下设置项：

- 默认风险偏好。
- 默认投资周期。
- 是否开启调试模式。
- 是否显示完整 Agent Trace。
- 是否默认进入 V2 分析。

### 3.5 历史研究页

可以作为独立页面，也可以先作为主研究页顶部或侧边入口。

用于查看过去的研究主题和每个研究线程。

## 4. 主研究页整体结构

主研究页建议采用“首屏输入 + 纵向研究流”的结构。

页面结构：

```text
顶部导航
  Logo / 首页 / 历史研究 / 设置 / 用户菜单

第一屏：研究入口
  大标题
  推荐提问浮窗
  大输入框
  风险偏好选择
  投资周期选择
  调试模式开关
  开始分析按钮

提交后向下展开：
  当前研究上下文
  第 1 轮用户问题
  第 1 轮 Agent 分析流程
  第 1 轮过程细节
  第 1 轮最终结论
  追问输入框

继续追问后：
  第 2 轮追问问题
  第 2 轮继承上下文说明
  第 2 轮 Agent 分析流程
  第 2 轮补充结论
  追问输入框

后续无限追加
```

## 5. 第一屏输入区设计

第一屏是用户进入系统后的核心视觉区域。

设计目标：

- 简洁、有高级感。
- 保持红黑金融科技风格。
- 让用户明确知道“可以问投资研究问题”。
- 推荐问题以浮窗或 chip 的形式展示，不要做成大量卡片。

建议结构：

```text
你想研究什么？

[ 分析宁德时代未来三个月的风险                         ]

风险偏好：稳健型      投资周期：三个月      调试模式：关闭

[开始分析]

推荐问题：
  分析宁德时代未来三个月风险
  沪深300ETF适合长期定投吗
  AAPL 当前估值贵不贵
  半导体行业近期有哪些风险
```

输入框要求：

- 尺寸较大，视觉上作为页面中心。
- 支持多行输入。
- 支持 Enter 提交，Shift + Enter 换行。
- 未登录时点击提交应引导登录。
- 提交后自动滚动到分析流程区域。

推荐问题要求：

- 使用红色弱高亮或半透明深色 chip。
- 点击后填入输入框。
- 不要用蓝色。

## 6. 研究线程模型

整个页面由多个研究回合组成。

每一个问题或追问都是一个 `ResearchTurn`。

建议前端状态模型：

```js
{
  turnId,
  parentTurnId,
  sessionId,
  taskId,
  query,
  queryType,
  inheritedContext,
  changedContext,
  status,
  progress,
  agentSteps,
  toolLogs,
  evidenceItems,
  criticResult,
  complianceResult,
  answer,
  error,
  createdAt,
  completedAt
}
```

字段说明：

- `turnId`：当前研究回合 ID。
- `parentTurnId`：如果是追问，则指向上一轮。
- `sessionId`：后端会话 ID。
- `taskId`：后端任务 ID。
- `query`：用户本轮问题。
- `queryType`：`initial`、`follow_up`、`compare`、`condition_change`。
- `inheritedContext`：继承的资产、证据、风险偏好、投资周期等。
- `changedContext`：本轮修改的条件，比如周期从三个月改成半年。
- `agentSteps`：Agent 执行过程。
- `toolLogs`：工具调用日志。
- `evidenceItems`：证据池。
- `criticResult`：事实与逻辑校验结果。
- `complianceResult`：合规校验结果。
- `answer`：最终结构化回答。

## 7. 研究回合展示设计

每一轮研究回合建议由以下模块组成：

```text
用户问题区
继承上下文区
Agent 工作流区
过程细节区
最终结论区
```

### 7.1 用户问题区

显示用户本轮问题。

首轮显示：

```text
主问题
分析宁德时代未来三个月的风险
```

追问显示：

```text
追问 1
那如果周期改成半年呢？
```

如果是对比追问：

```text
追问 2
和比亚迪相比哪个风险更高？
```

### 7.2 继承上下文区

追问场景必须显示“继承了什么、修改了什么”。

示例：

```text
继承上下文
资产：宁德时代 / A股 / 300750
风险偏好：稳健型
已复用证据：行情 2 条 / 新闻 4 条 / 知识库 1 条

本轮变化
投资周期：未来三个月 → 未来半年
```

如果新增资产：

```text
本轮扩展
新增资产：比亚迪 / A股 / 002594
分析类型：横向对比
```

### 7.3 Agent 工作流区

这是 V2 的核心展示区域。

Agent 应以纵向时间线展示，不建议放在三栏右侧。

建议展示的 Agent：

```text
01 ContextLoader      加载会话上下文
02 RouterAgent        识别意图
03 AssetResolver      识别资产
04 PlannerAgent       动态规划任务
05 ToolExecutor       执行工具
06 EvidenceAgent      整理证据
07 AnswerDraftAgent   生成草稿
08 CriticAgent        事实与逻辑校验
09 ComplianceAgent    合规校验
10 AnswerComposer     生成最终结论
```

每个 Agent 节点展示：

- Agent 名称。
- 当前状态：等待、运行中、已完成、失败、降级、跳过。
- 简短说明。
- 核心输出摘要。
- 耗时。
- 是否可展开查看细节。

示例：

```text
RouterAgent · 已完成 · 320ms
识别结果：资产分析 + 风险检查
需要能力：行情数据、新闻检索、知识库
```

```text
PlannerAgent · 已完成 · 210ms
生成计划：4 个工具调用
cn_stock_history / asset_news_search / investment_framework_search / analysis
```

```text
ComplianceAgent · 已完成 · 180ms
合规结果：通过
未出现确定性收益承诺或诱导交易表达
```

### 7.4 过程细节区

过程细节不建议全部默认展开，否则页面会过长。

建议使用当前区域内的 Tab 或折叠面板：

```text
过程细节
[工具调用] [证据池] [风险限制] [校验记录] [原始Trace]
```

默认展示：

- 工具调用摘要。
- 证据池摘要。
- 数据限制。
- Critic 和 Compliance 结果。

调试模式下展示：

- 原始 trace。
- 原始 tool params。
- 原始 tool result。
- 原始错误堆栈或错误摘要。

### 7.5 最终结论区

最终结论应该是报告形态，不是聊天气泡。

建议结构：

```text
总体结论
...

关键判断
1. ...
2. ...
3. ...

证据依据
- ...
- ...

情景分析
乐观情景：...
中性情景：...
悲观情景：...

主要风险
- ...
- ...

可选操作
- ...
- ...

数据限制
- ...

合规提示
...
```

该结构应对应后端 V2 的 `InvestmentAnswer`：

- `summary`
- `key_points`
- `evidence_refs`
- `scenarios`
- `risks`
- `action_options`
- `data_limitations`
- `compliance_disclaimer`

## 8. 追问设计

追问是本次前端重构的核心交互。

追问不是打开新页面，也不是替换当前内容，而是在同一个研究线程页面中继续追加新的研究回合。

### 8.1 追问输入框位置

追问输入框放在当前最后一个研究回合的结论下面。

每一轮完成后，页面底部出现：

```text
继续追问这份研究

当前上下文：
宁德时代 300750 · 未来三个月 · 稳健型 · 累计 8 条证据

[ 如果周期改成半年，结论会变化吗？             ][继续分析]
```

提交追问后：

- 不清空已有研究内容。
- 新增一个研究回合。
- 自动滚动到新增回合。
- 新增回合实时展示 Agent 分析过程。

### 8.2 追问类型

追问建议分为三类。

#### 8.2.1 同主题追问

示例：

```text
最大的风险是什么？
现在适合关注吗？
有哪些数据需要继续跟踪？
```

行为：

- 继承当前资产。
- 继承已有证据。
- 不一定重新进行完整资产识别。
- 重点调用 Planner、Evidence、Answer、Critic、Compliance。

前端显示：

```text
本轮追问继承：
资产：宁德时代 300750
证据：复用上一轮证据池
```

#### 8.2.2 条件变更追问

示例：

```text
如果周期改成半年呢？
如果我是激进型投资者呢？
如果只看基本面呢？
```

行为：

- 继承资产。
- 修改投资周期、风险偏好或分析角度。
- Planner 根据变化决定是否补查数据。

前端显示：

```text
本轮修改：
投资周期：三个月 → 半年
风险偏好：稳健型 → 激进型
```

#### 8.2.3 对比或扩展追问

示例：

```text
和比亚迪比呢？
再加上亿纬锂能一起比较
AAPL 和 NVDA 哪个估值压力更大？
```

行为：

- 新增资产。
- 进入对比分析。
- 需要补充新增资产的行情、新闻、知识证据。

前端显示：

```text
本轮扩展：
新增资产：比亚迪 002594
分析类型：横向对比
```

### 8.3 无限迭代页面

追问会形成无限延展页面：

```text
第 1 轮：主问题
  分析流程
  结论

第 2 轮：追问
  追问分析流程
  补充结论

第 3 轮：追问
  追问分析流程
  补充结论

...
```

注意：历史回合的过程详情默认折叠，只保留结论摘要。

建议规则：

- 当前正在运行的回合：默认展开完整 Agent 工作流。
- 已完成的历史回合：默认折叠 Agent 过程，只展示问题和结论摘要。
- 用户可以点击“展开过程”查看历史回合细节。
- 页面右下角可提供“回到最新分析”按钮。

## 9. SSE 流式可视化设计

后端通过 SSE 推送 Agent 过程事件，前端实时更新当前研究回合。

建议支持事件：

```text
task_started
node_started
node_completed
tool_started
tool_completed
evidence_added
draft_created
critic_completed
compliance_completed
task_completed
task_failed
heartbeat
```

事件映射：

| SSE 事件 | 前端表现 |
| --- | --- |
| `task_started` | 新增研究回合，状态为运行中 |
| `node_started` | 对应 Agent 节点变为运行中 |
| `node_completed` | 对应 Agent 节点变为已完成，显示摘要与耗时 |
| `tool_started` | 工具调用列表新增运行中工具 |
| `tool_completed` | 工具状态变为完成，展示结果摘要 |
| `evidence_added` | 证据池新增一条证据 |
| `draft_created` | 显示草稿已生成 |
| `critic_completed` | 显示 Critic 校验结果 |
| `compliance_completed` | 显示合规校验结果 |
| `task_completed` | 当前回合完成，展示最终结论 |
| `task_failed` | 当前回合失败，展示错误与可重试入口 |

### 9.1 当前运行状态

运行中的 Agent 节点应有明显状态：

- 轻微红色呼吸效果。
- loading 图标。
- 当前节点高亮。
- 页面自动滚动到当前执行节点。

不要使用大面积闪烁动画，避免影响阅读。

### 9.2 失败与降级

失败不是简单弹错，而是进入可解释状态。

示例：

```text
行情工具失败
原因：数据源暂时不可用
处理：已降级为新闻 + 知识库分析
影响：结论中将提示行情数据缺失
```

最终结论区需要展示 `data_limitations`。

## 10. 视觉风格

需要保持项目原本的红黑配色风格。

### 10.1 推荐色彩

```text
页面背景：#020617
次级背景：#0f172a
卡片背景：#111827 / #1e293b
卡片边框：rgba(255,255,255,0.08)
主红色：#dc2626
亮红色：#ef4444
橙色强调：#f97316
成功绿色：#22c55e
警告黄色：#f59e0b
失败红色：#ef4444
主文本：#f8fafc
次级文本：#94a3b8
弱文本：#64748b
```

### 10.2 风格要求

- 整体深色背景。
- 红橙渐变只用于核心按钮、Logo、重点状态，不要大面积滥用。
- 卡片尽量克制，边框细，背景深。
- 不使用蓝色作为主交互色。
- Agent 状态使用红色高亮当前执行节点。
- 成功、警告、失败状态分别使用绿色、黄色、红色。
- 页面要有投研产品的专业感，不要过度娱乐化。

## 12. 页面交互流程

### 12.1 首次分析流程

```text
用户进入首页
  ↓
点击开始研究
  ↓
进入 V2 主研究页
  ↓
输入问题或点击推荐问题
  ↓
点击开始分析
  ↓
创建第 1 个 ResearchTurn
  ↓
建立 SSE 连接
  ↓
实时展示 Agent 工作流
  ↓
展示工具日志和证据池
  ↓
展示 Critic 与 Compliance 校验
  ↓
展示最终结论
  ↓
出现追问输入框
```

### 12.2 追问流程

```text
用户在底部追问框输入问题
  ↓
提交时携带 session_id 和用户偏好
  ↓
创建新的 ResearchTurn
  ↓
展示继承上下文和本轮变化
  ↓
继续通过 SSE 展示本轮 Agent 分析过程
  ↓
追加本轮补充结论
  ↓
再次出现追问输入框
```

## 13. 需要重点体现的项目细节

前端展示需要和后端 V2 设计对应。

### 13.1 RouterAgent

展示：

- 问题意图。
- 是否追问。
- 是否需要实时数据。
- 是否需要新闻。
- 是否需要宏观。
- 风险偏好和投资周期。

### 13.2 AssetResolver

展示：

- 识别到的资产。
- 资产类型。
- 代码。
- 市场。
- 置信度。
- 歧义候选。

### 13.3 PlannerAgent

展示：

- 本轮目标。
- 计划步骤。
- 选择了哪些工具。
- 为什么选择这些工具。
- 是否有 stop condition。

### 13.4 ToolExecutor

展示：

- 工具名。
- 工具用途。
- 执行状态。
- 耗时。
- 结果摘要。
- 失败原因。

### 13.5 EvidenceAgent

展示：

- 证据类型。
- 来源。
- 摘要。
- 置信度。
- 重要性。
- 数据时间。
- 限制说明。

### 13.6 CriticAgent

展示：

- 是否通过。
- 分数。
- 发现的问题。
- 要求修订的内容。
- 缺失证据。

### 13.7 ComplianceAgent

展示：

- 是否通过。
- 是否阻断。
- 高风险表达检查。
- 是否已添加风险提示。
- 是否存在诱导交易。

## 14. 设计注意事项

- 不要把页面做成传统后台三栏布局。
- 不要把 Agent 过程藏在右侧小面板里。
- 不要把最终结论做成普通聊天气泡。
- 不要让追问替换原有分析内容。
- 不要默认展开所有历史回合的详细日志。
- 不要使用蓝色作为主色。
- 不要让日志内容过度技术化，普通模式要面向用户可读。
- 调试模式可以展示完整 raw trace。
- 当前正在运行的研究回合必须视觉上最突出。
- 历史研究回合要可折叠，保证无限追问时页面仍然可读。
