# Agent 结论严谨度与可信度优化方向

> 状态:P0/P1/P2 已实施
> 日期:2026-08-06
> 目标:让多 Agent 系统产出的投资结论更加严谨、准确、可信,并让前端可量化展示"可信度"
> 更新:2026-08-06 P0 两方案已实施;P1 两方案已实施;P2 三方向已实施(结构化风险/口径核验/缺口回流)

## 一、背景与现状

当前系统为"编排 Agent 按需调度 → 三个调研 Agent 并行研究 → 总结 Agent 综合输出"的多 Agent 架构。已有基础质量机制:

| 机制 | 位置 | 说明 |
|------|------|------|
| 无进展单调性检测 | `loop.py` | 连续无进展自动收敛 |
| 强制收敛 | `loop.py` | 达到工具调用上限强制结束 |
| 证据引用 | `state.py` `AgentResult.evidence_refs` | 工具调用 → 资产关联 |
| 降级标记 | `summary_agent.py` | `degraded` 标记研究过程异常 |
| 合规约束 | 各 Agent prompt | 不输出确定性买卖建议 |
| L3 沉淀 | `indexer.py` | 研究结论质量管控后写回知识库 |

但存在以下**结构性弱点**:

1. **调研 Agent 是信息孤岛**——三个 Agent 完全并行、互不知晓,交叉验证只在汇总末端做一次
2. **置信度是二值**(1.0 / 0.5)——不反映工具成功率、证据覆盖度、信息缺口
3. **推理是事后叙述**——模型先定结论再补 reasoning,而非先论证后结论
4. **关键数字无口径标注与双源核验**——PE 是动态还是 TTM 不明确,数据冲突不提示
5. **风险只有文字,无量级**——无"概率 + 影响"结构化表达
6. **信息缺口不回流**——`information_gaps` 只展示,不参与置信度决策

## 二、优化点(按优先级排序)

### P0-调研 Agent 间实时信息共享(核心:解决并行调研的信息孤岛)

**问题本质**:三个调研 Agent 并行运行、互不知晓。MarketAgent 查行情时不知道 NewsAgent 已发现"公司财报暴雷";KnowledgeAgent 检索到"该行业应看库存周期"但 MarketAgent 不会据此查库存数据。若调研方向在过程中就错了,末端 SummaryAgent 汇总无法补救。

**目标**:让调研 Agent 在**调研过程中**实时看到其他 Agent 的发现,据此调整自己的工具调用方向;并保证每个 Agent 的**最终结论**基于"自己调研 + 全部其他 Agent 发现"的完整信息。

#### 核心设计:共享发现池 + 两段式 Agent 执行(已定稿)

**四条设计决策(2026-08-06 确认)**:
1. **定位**:调研 Agent 段2 产出"修正领域结论",SummaryAgent 仍负责最终投资结论(职责不重叠)
2. **充分自由**:不做显式调用数量/次数限制,Agent 自行决定调研与核实方式;只保留防无限循环兜底
3. **两段式**:保留第一轮并行调研 + 第二轮补充调研,但无显式调用限制,Agent 自由发挥
4. **去重不限额**:发现池做相似去重,不做严格数量限制

```

                    ┌─────────────────────────────┐
                    │ findings: [{agent, text, ts}]│  ← 去重存储,不限额
                    └─────────────────────────────┘
                                   ▲ 广播 / 读取
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
  MarketAgent                 NewsAgent               KnowledgeAgent
  ┌───────────────────┐   ┌───────────────────┐   ┌───────────────────┐

  └───────────────────┘   └───────────────────┘   └───────────────────┘
```

#### 关键机制一:实时广播(第一轮调研过程中)

- 调研 Agent 的 ReAct 循环中,每轮工具调用后,由 LLM 从工具结果提炼**关键发现**(事实性,如"宁德时代 Q2 营收同比-15%")
- prompt 增加指令:"若工具结果包含重大事实,以 `[FINDINGS] 文本` 前缀输出广播"
- `loop.py` 解析 `FINDINGS:` 前缀 → 写入 `SharedFindingsPool.publish(agent, finding)`
- 池内每条带 `{agent, text, ts}`,**相似内容去重**(embedding 或文本相似度),**不做数量限制**

#### 关键机制二:实时消费(第一轮调研过程中)

- 每个 Agent 每轮 LLM 决策前,读取池中**自上次读取以来**的新发现(增量,避免重复)
- 拼接到本轮 user message:
  ```
  【其他研究员最新发现,供参考】
  [NewsAgent] 宁德时代 Q2 营收同比-15%,电池价格战加剧
  [KnowledgeAgent] 锂电池行业应跟踪产能利用率与碳酸锂价格
  如与你当前研究目标相关,可考虑据此调整后续工具调用方向;不相关则忽略。
  ```
- 用"仅供参考"弱化指令,避免被无关发现带偏;Agent 自行判断相关性
- **重大且影响结论的发现,Agent 可自行决定是否调工具核实**(不设次数限制)

#### 关键机制三:两段式(解决"先完成收不到后完成")

**问题**:三个 Agent 调研时长差异大,第一轮先完成的若立即出结论,会错过后来者广播的发现。

**解决**:改为**两段式**——第一轮并行调研 + 第二轮补充调研,由 Orchestrator 协调:

**第一轮**(现有并行逻辑):
1. 三个 Agent 并行调研,过程中实时广播/消费发现
2. 每个 Agent 主动收敛(受 `max_iterations` 兜底保护,不设其他限制)
3. Orchestrator 等全部 Future 完成

**汇聚**(Orchestrator):
4. 收集每个 Agent 第一轮产出的全部发现 → 汇总成**完整共享池**(去重后)

**第二轮**(新增,仍是并行):
5. 每个 Agent 带着"完整共享池(全部其他 Agent 发现)"**再跑一轮 ReAct**
6. 由 Agent 自行判断:哪些发现影响自己的结论?是否需要调工具核实/补充?
7. 收敛后输出**修正领域结论**(作为 `AgentResult.conclusion`)

**为什么这样解决了问题**:
- 第一轮收敛只是"阶段性成果",最终结论在第二轮产出
- 第二轮天然拿到**全部**发现(包括收敛后才广播的),不存在"收不到"
- 无线程阻塞等待(Orchestrator 用 `as_completed` 等即可),时序清晰可控
- 唯一的兜底是每个 Agent 的 `max_iterations`(防无限循环),不做调用次数限制

#### 时序图(两段式)

```
时间 →
第一轮:
MarketAgent:  ██调研██ ▶findings ██调研██ ▶收敛
NewsAgent:    ██调研██ ██调研██ ▶findings ▶收敛
Knowledge:    ██调研██ ▶findings ██调研██ ██调研██ ▶收敛
                     ↑
             池实时累积发现(仅对仍在调研的Agent实时生效)
               ↓
Orchestrator: 等全部Future完成 → 汇总完整池(去重)
               ↓
第二轮:
MarketAgent:  [完整池] ██补充调研██ ▶修正领域结论
NewsAgent:    [完整池] ██补充调研██ ▶修正领域结论
Knowledge:    [完整池] ██补充调研██ ▶修正领域结论
               ↓
SummaryAgent: 基于三个修正领域结论 + 完整池 → 最终投资结论
```

#### 与 SummaryAgent 的关系

- 调研 Agent 第二轮产出的**修正领域结论**作为 `AgentResult.conclusion` 传给 SummaryAgent(现有逻辑不变)
- 完整共享池同时注入 SummaryAgent 上下文,SummaryAgent 综合时可见全部原始发现
- **SummaryAgent 负责最终投资结论**(职责唯一,不重复)

#### 实施备注

- **性能影响**:第二轮新增一轮并行调研,成本 ≈ 一次 ReAct 循环/Agent;换来自动方向修正与信息补全
- **兜底**:仅 `max_iterations` 防无限循环;不做调用次数/轮次硬限制(给 Agent 充分空间)
- **发现质量**:池做相似去重(SequenceMatcher ≥0.88),不做数量限制;消费侧"仅供参考,重大自行核实"
- **上下文膨胀**:第一轮实时注入只取增量;第二轮注入完整池(去重后通常 <50 条,可控)

#### 测试验证(已通过 ✅)

- **共享池**:广播/去重(重复文本不重复写入)/增量读取(get_since)/格式化注入,均正确
- **并发安全**:3 线程并发广播 30 条,池长度 30,无数据竞争
- **两段式协调**(stub Agent 注入):第一轮各 Agent 广播发现 → 第二轮每个 Agent 看到全部 3 个 Agent 的发现 → 输出修正结论
- **真实链路**:后端 create_app OK;三个调研 Agent 实例化 OK;第二轮 prompt/user message 正确携带共享发现
- **边界**:池为空时跳过第二轮(直接返回第一轮结果),不影响原有单 Agent 场景

### P0-证据回查(已简化为 SummaryAgent 全工具)

**原方案**:SummaryAgent 发现矛盾时向 Orchestrator 发起"回查请求",由 Orchestrator 派发定向补充调研。

**决策(2026-08-06)**:不做回查协议,直接**让 SummaryAgent 使用全部工具**。
- SummaryAgent 本身是 ReAct 循环(思考→调工具→观察),扩展 `tool_names` 为全部即可
- 它发现矛盾时自己判断该验证什么、直接调工具核实(如调 `cn_stock_spot_search` 核对 PE 口径),无需 Orchestrator 中转
- 已有收敛机制(`max_iterations` 上限 + 无进展检测)兜底,不会失控
- 唯一注意:prompt 约束"只在综合需要时调用 1-2 次,一次到位",避免像调研 Agent 一样反复调工具

### P1-置信度评分体系(已实施 ✅)

**现状**:`summary_agent.py` 中 `confidence = 1.0 if not degraded else 0.5`,只有降级才扣分。

**已实施**(`summary_agent.py._compute_confidence`):
```
confidence = 模型自评(0~1),无自评用 0.85 基准
- degraded → 直接压到 ≤0.4
- 信息缺口 ≥3 扣 0.1;≥5 再扣 0.1
- 工具失败率 >50% 扣 0.1
- 多空论据单边(缺 bull 或 bear)扣 0.05
```
- SummaryAgent prompt 增加"置信度 < 0.6 时 summary 必须显著标注'不确定性较高'"
- 前端按置信度分档展示:`≥0.8 高可信 / 0.6~0.8 中可信 / <0.6 低可信`
- 测试验证:9 个场景(正常/缺口3/缺口5/工具失败/单边论据/degraded/无自评)全部符合预期

### P1-论据前置的结构化推理(已实施 ✅)

**现状**:prompt 要求输出 `reasoning`,但模型往往"先定结论、再补推理"。

**已实施**(`summary_agent.py` prompt + `state.py` 字段 + 前端):
- 输出结构改为论据前置:`bull_cases / bear_cases / decision / confidence`
- 每条论据带 `{point, strength(high/medium/low), source}`
- 前端 SummaryCard 新增"多空论据"对比面板(红绿两栏)+ 置信度标签

**测试验证**(同一份宁德时代调研上下文,真实 LLM 对比):
| 维度 | 旧 prompt | 新 prompt |
|------|-----------|-----------|
| bull_cases 结构化论据 | ❌ 无(混在 reasoning 文本) | ✅ 有(带强度+来源) |
| bear_cases 看空论据 | ❌ 无 | ✅ 有 |
| confidence 置信度 | ❌ 无 | ✅ 有 |
| 论据来源标注 | ❌ 无 | ✅ 每条带 MarketAgent/NewsAgent/KnowledgeAgent |

结论:论据前置确实优化了输出——模型被强制先列多空论据(带来源与强度)再给结论,不再"先定结论后补理由",且信息可结构化展示。

### P2-关键数据口径标注与双源核验(已实施 ✅)

**建议**:
1. 行情/财务工具返回时在 `summary` 中标注口径(如"市盈率-TTM")
2. SummaryAgent 对关键数字(涨跌幅、PE、成交额)做**双源核验**:两个工具/接口对不上时标注"数据冲突待核验",而非直接用
3. 复用知识库《指标口径说明》作为核验参照

**已实施**(`summary_agent.py` prompt 新增【双源核验】节):
- 对关键数字(涨跌幅、PE/PB、成交额)尽量做双源核验;不同工具数据不一致时标注"数据冲突待核验",不得直接采用单一来源数字
- 引用估值指标时注明口径(如"PE(TTM)" vs "PE(动态)"),口径不同不可直接比较

### P2-结构化风险模型(已实施 ✅)

**现状**:`risks` 是字符串列表。

**已实施**(`state.py` + `summary_agent.py` + 前端):
- `InvestmentAnswer` 新增 `structured_risks` 字段:
```json
{"type": "行业/财务/政策/市场/流动性/技术", "desc": "...", "probability": "high/medium/low", "impact": "high/medium/low", "priced_in": true/false/null}
```
- `_parse_structured_risks()`:兼容中英文键;无效时把字符串 `risks` 兜底转为 `type=其他`
- 前端 SummaryCard:结构化风险以**风险矩阵表格**展示(类型/描述/概率/影响/是否已反映在价格),字符串 risks 作为回退
- prompt 明确 structured_risks 与 risks 二选一(结构化优先)
