# 前后端联调修复设计

## 1. 目标

本次修复仅解决已确认的前后端联调问题，不扩展新功能。

修复目标如下：

1. 后端默认启动端口改为 `5001`，避免本机 `5000` 端口冲突。
2. 前端默认 API 基址与后端默认端口保持一致。
3. 历史研究页与研究工作台会话列表统一走现有 API 客户端封装。
4. 前端统一使用 `auth_token` 作为登录态存储键名。
5. 测试默认配置与新的默认端口保持一致。

## 2. 变更范围

### 2.1 后端

- `src/api/main.py`

变更内容：

- 将 `app.run()` 默认端口从 `5000` 调整为 `5001`。

### 2.2 前端服务层

- `src/web/src/services/apiClient.js`
- `src/web/src/services/apiV2Service.js`
- `src/web/src/services/apiService.js`

变更内容：

- 确认默认 API 基址统一为 `http://localhost:5001`。
- 不新增新的服务抽象，继续沿用现有封装。

### 2.3 前端页面

- `src/web/src/components/views/HistoryView.jsx`
- `src/web/src/components/research/SessionList.jsx`

变更内容：

- 删除组件内对 `fetch('/api/chat/sessions')` 的直接调用。
- 删除组件内手动读取 `localStorage.getItem('token')` 的逻辑。
- 改为调用 `apiClient.js` 中已有的 `getChatSessions()`。
- 由统一 API 客户端负责附加 `Authorization` 请求头。

### 2.4 测试与默认配置

- `tests/conftest.py`
- `tests/test_api_endpoints.py`
- `tests/test_integration.py`

变更内容：

- 将后端默认端口改为 `5001`。
- 保留通过环境变量覆盖端口的能力。
- 不调整前端默认端口 `5173`。

## 3. 数据流调整

修复前：

1. 用户登录后，token 写入 `auth_token`。
2. `HistoryView.jsx` 与 `SessionList.jsx` 却读取 `token`。
3. 两个组件直接请求 `/api/chat/sessions`。
4. 在开发环境中，请求进入 Vite 服务而不是 Flask 后端。

修复后：

1. 用户登录后，token 继续写入 `auth_token`。
2. 页面组件不再直接读取本地 token。
3. 页面组件统一调用 `getChatSessions()`。
4. `apiClient.js` 统一读取 `auth_token` 并拼接完整后端地址。
5. 请求稳定发送到 `http://localhost:5001/api/chat/sessions`。

## 4. 错误处理原则

本次修复不额外扩展错误处理框架，仅保持现有风格：

- 页面加载失败时维持当前降级表现，如展示空列表或保留现有日志输出。
- 不新增全局状态管理。
- 不引入 Vite 代理作为主修复方案。

## 5. 验证方案

修复完成后执行以下验证：

1. 启动后端：`python run.py --backend`
2. 启动前端：`python run.py --frontend`
3. 请求 `http://127.0.0.1:5001/api/health` 应返回 `200`
4. 请求 `http://127.0.0.1:5001/api/agent/v2/health` 应返回 `200`
5. 前端页面访问后，不应再把会话列表请求打到 `5173/api/chat/sessions`
6. 搜索前端代码时，不应再存在 `localStorage.getItem('token')`
7. 历史研究页和研究工作台会话列表应通过统一 API 客户端获取数据

## 6. 范围约束

本次修复明确不包含以下内容：

- 不新增新的前端页面。
- 不改造认证机制本身。
- 不引入新的接口协议。
- 不对无关模块做顺手重构。
- 不默认增加 Vite 代理配置。

## 7. 实施顺序

1. 修改后端默认端口。
2. 核对前端默认 API 基址。
3. 修复 `HistoryView.jsx`。
4. 修复 `SessionList.jsx`。
5. 同步修正测试默认端口。
6. 启动前后端并进行实际验证。
